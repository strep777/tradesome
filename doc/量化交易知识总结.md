## 1. 先建立正确认知

### 1.1 量化交易是什么

量化交易 = **用数据和程序，把交易决策变成可量化、可执行、可复现的规则**。

它把"我觉得要涨"换成"当 5 日均线上穿 20 日均线、且成交额大于 20 日均额的 1.5 倍时，用 10% 仓位买入"。区别不在聪明程度，而在**可检验**：规则写死了，就能拿历史数据反复验证，也能在实盘里被程序不折不扣地执行。

三个关键词：

| 关键词 | 含义 | 反面 |
|---|---|---|
| 可量化 | 信号能用数字表达 | "感觉要涨" |
| 可执行 | 程序能自动下单 | 需要盯盘手工操作 |
| 可复现 | 同样输入得到同样输出 | 每天判断都不一样 |

### 1.2 量化靠什么赚钱

很多人以为量化是"预测未来"。不是。主流的收益来源只有三类：

1. **定价偏差（套利/均值回归）**：价格短期偏离价值，等它回归。比如两只高度相关的 ETF 价差突然拉大。
2. **风险补偿（风险溢价）**：你承担了别人不愿承担的风险，市场付你钱。比如动量因子、小市值因子、持有高波动资产。
3. **执行效率（微观结构）**：比别人更快、更便宜地成交。做市、拆单、减少冲击成本。

对应到个人开发者，最现实的是第 2 类（因子/趋势）和第 1 类（均值回归），第 3 类需要硬件和通道优势。

**关键结论**：策略赚的是"统计上的优势"，单笔结果随机，只有重复足够多次、优势足够稳定，期望才为正。所以：

- 胜率 40% 但盈亏比 3:1 的系统，长期是赚的；
- 胜率 90% 但每次赚 1 块、亏 30 块（网格死扛、卖期权），一次极端行情就归零。

### 1.3 量化不是稳赚，也不是圣杯

必须接受的五个事实：

1. 回测赚钱 ≠ 未来赚钱，回测只是"取得参赛资格"；
2. 策略会失效（市场结构变化、拥挤、监管变化），需要持续监控与迭代；
3. 成本（手续费+印花税+滑点+冲击）能吃掉大部分短周期策略的利润；
4. 黑天鹅一定会有，风控决定你能不能活到下一次机会；
5. 大部分时间你是在写代码、洗数据、修 bug，不是在"交易"。

### 1.4 什么人适合做量化

- 愿意花几个月学 Python 和统计，能忍受长时间没有正反馈；
- 有工程能力（或愿意学）：数据清洗、回测框架、日志、部署；
- 有纪律：能接受程序给出的止损，不手动干预；
- 有亏得起的闲钱。

不适合：想找"圣杯参数"、想快速暴富、无法接受回撤、不愿意写代码的人。

## 2. 市场与交易规则（决定你的代码怎么写）

写交易软件，第一件事不是写策略，而是把**市场规则**翻译成代码里的约束。下面以 A 股为主。

### 2.1 交易时间（北京时间）

| 时段 | 内容 | 代码含义 |
|---|---|---|
| 9:15–9:25 | 开盘集合竞价 | 9:20 后不可撤单 |
| 9:25–9:30 | 撮合结果公布，不接受委托 | 静止期 |
| 9:30–11:30 | 上午连续竞价 | 主交易时段 |
| 11:30–13:00 | 午休 | 停止撮合 |
| 13:00–14:57 | 下午连续竞价 | 主交易时段 |
| 14:57–15:00 | 收盘集合竞价（沪深） | 不可撤单 |

交易日 = 工作日 − 法定节假日。**节假日不是周末**，必须用交易日历，不能简单 `weekday() < 5`。

### 2.2 核心规则表

| 规则 | 内容 | 对回测/实盘的影响 |
|---|---|---|
| T+1 | 当日买入的股票，次一交易日才能卖出 | 回测里必须记录"可卖数量"，当日买入的不能当天平仓 |
| 最小单位 | 买入 100 股（1 手）的整数倍；科创板 200 股起、可 1 股递增 | 下单数量必须取整，资金少时可能买不起一手 |
| 涨跌停 | 主板 ±10%，创业板/科创板 ±20%，北交所 ±30%，ST ±5% | 涨停买不进、跌停卖不出；撮合时要做"封板"判断 |
| 价格笼子 | 连续竞价限价单有申报价格范围限制（各板块不同） | 极端价格委托会被交易所拒绝 |
| 停牌 | 重大事项停牌，无法交易 | 回测要处理缺失 bar |
| 除权除息 | 分红送股导致价格跳空 | 必须用**复权**数据，否则指标全错 |
| 卖出费用 | 印花税仅卖出收取 | 成本模型必须区分买卖 |

### 2.3 交易费用（2024 年前后常见水平，务必按券商实际调整）

| 费用 | 收取方式 | 常见费率 | 备注 |
|---|---|---|---|
| 佣金 | 买卖双向 | 万分之 2.5 ~ 万分之 3 | **单笔最低 5 元**（不足 5 元按 5 元收） |
| 印花税 | 仅卖出 | 成交额的 0.05%（万 5） | 2023 年 8 月起由 0.1% 减半 |
| 过户费 | 买卖双向 | 成交额的 0.001%（万 0.1） | 沪深两市均收 |
| 规费 | 通常已含在佣金中 | — | 问清券商 |

**算一笔账**：买入 10 万元股票，佣金万 2.5 = 25 元，过户费 1 元，合计 26 元；卖出时再加印花税 50 元，合计 76 元。**一次完整买卖往返成本约 0.102%**。

这对策略意味着什么？

- 日均换手 1 次的策略，一年 250 次往返 → 成本约 25.5% 的收益被吃掉；
- 所以**高频策略必须有极高的单次胜率/盈亏比**，否则做的是"给券商打工"；
- 小资金注意"最低 5 元佣金"：1 万元的单笔交易，佣金 5 元 = 万 5，实际费率翻倍。

> 软件里这些参数必须全部可配置（`core/config.py` 的 `CostConfig`），并在回测报告中单列"总成本"。

### 2.4 不同品种的差异（做通用软件时要抽象）

| 品种 | T+0 | 涨跌停 | 最小单位 | 备注 |
|---|---|---|---|---|
| A 股股票 | 否 | ±10%/20%/30% | 100 股 | 本文默认对象 |
| 股票型 ETF | 否（跨境/债券/黄金 ETF 多为 T+0） | ±10% | 100 份 | 免印花税 |
| 可转债 | 是 | ±20%（首日 ±57.3%/±43.3%） | 10 张 | 免印花税，T+0 |
| 股指期货 | 是 | ±10% | 1 手 | 保证金、当日无负债结算 |
| 商品期货 | 是 | 各品种不同 | 1 手 | 保证金、夜盘、合约换月 |

**软件设计含义**：把这些差异做成 `Instrument` 的字段（`t_plus`、`price_limit`、`lot_size`、`fee_profile`、`session`），策略层只调用 `buy/sell`，由执行层按品种规则校验。这样加新市场不用改策略。

## 3. 数据：量化的原料

### 3.1 K 线（Bar）是什么

一根日 K 线包含：

| 字段 | 含义 |
|---|---|
| `datetime` |  bar 结束时间（日线通常记为当日 15:00 或当日日期） |
| `open` | 开盘价 |
| `high` | 最高价 |
| `low` | 最低价 |
| `close` | 收盘价 |
| `volume` | 成交量（股/手） |
| `amount` | 成交额（元），可选但强烈建议保留 |

**常见错误**：把 `datetime` 记成 bar 开始时间，导致回测里"用当天收盘价在当天开盘成交"——这就是未来函数的一种。

### 3.2 复权：不复权 = 指标全错

股票分红送股后价格会跳空。例如 10 送 10，股价从 20 元变 10 元，如果不复权，均线会出现一个 -50% 的假暴跌。

| 类型 | 做法 | 用途 |
|---|---|---|
| 不复权 | 原始成交价 | 看真实成交价、计算税费 |
| 前复权 | 以当前价为基准调整历史价 | **回测/画图默认用这个** |
| 后复权 | 以上市首日为基准调整 | 长期收益计算、避免负数 |

前复权的坑：每次除权后历史数据会整体变化，**同一份数据隔月重跑结果可能不同**。工程上要记录数据版本（`data_version`）。

### 3.3 数据源

| 类型 | 代表 | 优点 | 缺点 |
|---|---|---|---|
| 免费开源 | AkShare、Tushare（积分制）、efinance | 零成本、上手快 | 稳定性一般、字段不统一、限频 |
| 券商接口 | QMT/miniQMT、Ptrade、恒生 | 可实盘、数据全 | 需开户/资金门槛、Windows 绑定 |
| 付费数据商 | Wind、聚宽、米筐 | 质量高、有因子库 | 贵 |
| 交易所/官网 | 上交所、深交所 | 权威 | 需要自己解析 |

**个人项目建议**：研究阶段用 AkShare 拉日线（前复权），落库成 CSV/SQLite；实盘阶段接券商 QMT/Ptrade。**不要把策略和数据源耦合**——用 `MarketDataProvider` 接口隔离，换源只改一个适配器。

### 3.4 数据质量校验清单

拿到数据先做这 8 项检查（软件里 `data/quality.py` 会做）：

1. 是否有重复时间戳；
2. 时间是否严格递增、是否有缺口（停牌/节假日）；
3. `high >= max(open, close)`、`low <= min(open, close)`；
4. `volume >= 0`、`amount >= 0`；
5. 价格是否 <= 0；
6. 单日涨跌幅是否超过该板块涨跌停限制（超过说明未复权或有错）；
7. 是否有长期不变的"僵尸价格"（停牌未标记）；
8. 复权因子是否缺失。

**垃圾进垃圾出**：一个未复权的数据集，能让任何策略的回测结果失真 20% 以上。

### 3.5 存储选型

| 方案 | 适用 | 说明 |
|---|---|---|
| CSV | 小数据、可交换 | 人类可读、便于用户导入 |
| Parquet | 大数据、列式查询 | 快，但需要额外依赖 |
| SQLite | 单机桌面软件 | **零依赖、事务安全、够用**（百万行日线毫无压力） |
| 时序数据库 | 高频/多标的 | InfluxDB、ClickHouse，个人项目一般不需要 |

TradeSome 选择 SQLite：主键 `(symbol, timeframe, datetime)`，加索引 `(symbol, datetime)`，千万行以内性能足够。

## 4. 策略：把想法变成规则

### 4.1 一个策略必须回答的五个问题

1. **选什么**（标的池）：全市场？沪深 300？自选 10 只？
2. **什么时候买**（入场信号）：均线金叉？突破 20 日高点？RSI < 30？
3. **买多少**（仓位）：固定金额？固定比例？按 ATR 波动率调整？
4. **什么时候卖**（出场信号）：死叉？止损？止盈？持有 N 天？
5. **什么时候不做**（过滤条件）：大盘下跌时空仓？波动率过高不交易？

只回答第 2 个问题的，叫"信号"，不叫"策略"。**仓位和出场往往比入场更重要**。

### 4.2 六大策略族

#### （1）趋势跟踪（Trend Following）

**直觉**：涨的会继续涨（动量效应），跌的会继续跌。

**典型实现**：双均线交叉、唐奇安通道突破、MACD 金叉。

```
快线 = SMA(close, 5)
慢线 = SMA(close, 20)
快线上穿慢线 → 买入
快线下穿慢线 → 卖出
```

**参数**：快线周期、慢线周期、止损 ATR 倍数。

**优点**：逻辑简单、容量大、能抓住大趋势。
**缺点**：震荡市反复打脸（假突破），胜率通常只有 35%–45%，靠盈亏比赚钱。
**失效场景**：长期横盘、政策市急涨急跌。

#### （2）均值回归（Mean Reversion）

**直觉**：价格偏离均值太远会回来。

**典型实现**：布林带（跌破下轨买入、回到中轨卖出）、RSI 超卖买入、配对交易（两只相关标的价差回归）。

```
中轨 = SMA(close, 20)
上轨 = 中轨 + 2 × STD(close, 20)
下轨 = 中轨 − 2 × STD(close, 20)
收盘价 < 下轨 → 买入；收盘价 >= 中轨 → 卖出
```

**优点**：震荡市胜率高（60%–70%）。
**缺点**：趋势市"接飞刀"，一次单边下跌能把几个月利润亏光。**必须配硬止损**。

#### （3）网格交易（Grid）

**直觉**：在价格区间内，每跌一格买一份，每涨一格卖一份，吃震荡。

**实现**：设定基准价、网格间距（百分比或 ATR）、每格数量、上下边界。

**优点**：震荡市现金流稳定，容易理解，适合 ETF。
**缺点**：单边下跌会不断加仓直到弹尽粮绝（"网格破网"）；单边上涨会过早卖光（"卖飞"）。**必须有总仓位上限和破网止损**。

#### （4）动量轮动（Momentum Rotation）

**直觉**：在多个标的间，买入近期最强的 N 个，定期换仓。

**实现**：
```
每 20 个交易日：
  对池内每个标的计算过去 20 日收益率
  剔除收益率 < 0 的（或跌破 60 日均线的）
  买入排名前 K 的，等权/按波动率倒数加权
  调出排名的卖出
```

**优点**：天然分散、适应风格切换、容量大。
**缺点**：换手高（成本敏感）、牛市末期追高、需要多标的行情。

#### （5）多因子选股（Factor Investing）

**直觉**：某些特征（低估值、高动量、低波动、高质量）长期有超额收益。

**实现**：
1. 每月在股票池内计算因子值（PE、ROE、20 日动量、60 日波动率等）；
2. 标准化（Z-score）并加权合成综合分；
3. 买入前 N 名，等权，月度调仓；
4. 行业/市值中性化处理，避免押注单一风格。

**优点**：逻辑扎实、可解释、容量大。
**缺点**：需要财务数据、处理缺失值麻烦、因子会拥挤失效。

#### （6）事件/情绪驱动

**直觉**：财报超预期、政策发布、舆情情绪会带来短期定价偏差。

**实现**：把文本（财报、新闻、公告）转成 -1/0/1 的情绪分，叠加技术面过滤。常见做法是用 LLM 读"管理层讨论与分析"，输出看多/中性/看空，再与传统因子合成。

**优点**：信息增量大、与传统策略相关性低。
**缺点**：数据获取难、延迟高、容易过拟合、LLM 输出不稳定（temperature 要低、要多次投票）。

> 参考的知乎文章《2026 DeepSeek A股量化策略完整教程》给了一个三层结构：**传统因子筛 50 只 → LLM 财报分析精选 10 只 → 风控模块最终持 5 只**。这个"粗筛→精选→风控"的分层思想比具体模型更值得抄。TradeSome 的 `momentum_rotation` 与 `sentiment_boost` 两个内置策略即受此启发，其中情绪源做成可插拔（本地 CSV / 可选 DeepSeek API），离线也能跑。

### 4.3 策略参数不是越多越好

每多一个参数，就多一个过拟合的维度。经验法则：

- 参数不超过 4 个；
- 参数在合理范围内应"平台稳定"（参数微调，绩效不崩），而不是尖峰；
- 用**样本外**数据验证，用**滚动窗口**（walk-forward）检验稳定性；
- 优先选择经济学上说得通的参数（如 20 日 ≈ 一个月）。

### 4.4 策略代码的接口设计（TradeSome 约定）

```python
class Strategy:
    params = {"fast": 5, "slow": 20}      # 声明式参数，UI 自动生成表单
    def on_start(self, ctx): ...           # 初始化
    def on_bar(self, ctx, bar): ...        # 每根 K 线调用一次（只含已发生数据）
    def on_order(self, ctx, order): ...    # 订单状态变化
    def on_stop(self, ctx): ...            # 收尾
```

`ctx` 提供 `ctx.buy(size, ...)`、`ctx.sell(...)`、`ctx.position`、`ctx.history(n)`、`ctx.indicator(...)`。**策略只表达"想做什么"，不直接碰数据库、网络、UI**——这是模块可独立替换的前提。

## 5. 技术指标：公式、用途与陷阱

所有指标都只是"价格的函数"，不包含新信息。它们的价值在于**把某种市场行为标准化**，方便写规则。

| 指标 | 公式 | 用途 | 陷阱 |
|---|---|---|---|
| SMA | `mean(close, n)` | 趋势方向、支撑阻力 | 滞后；对参数敏感 |
| EMA | `EMA_t = α·P_t + (1−α)·EMA_{t−1}`，`α=2/(n+1)` | 更灵敏的趋势 | 更易被噪音骗 |
| MACD | `DIF=EMA12−EMA26`；`DEA=EMA9(DIF)`；`柱=2×(DIF−DEA)` | 趋势与动能 | 震荡市反复金叉死叉 |
| RSI | `RSI = 100 − 100/(1+RS)`，`RS=平均涨幅/平均跌幅` | 超买超卖 | 强趋势中 RSI 可长期 >70 |
| BOLL | 中轨 SMA20，上下轨 ±2σ | 波动率通道、均值回归 | 突破上轨也可能是趋势启动 |
| ATR | `TR=max(H−L, |H−C_prev|, |L−C_prev|)`；`ATR=EMA(TR,14)` | 波动率、止损距离、仓位 | 跳空缺口会放大 ATR |
| KDJ | `K=2/3·K_prev+1/3·RSV`；`D=2/3·D_prev+1/3·K`；`J=3K−2D` | 短期超买超卖 | 参数敏感、噪音大 |
| ROC | `(close_t/close_{t−n}−1)×100` | 动量强度 | 对起点敏感 |
| Donchian | `上轨=max(high, n)`；`下轨=min(low, n)` | 突破系统 | 震荡市假突破 |
| 波动率 | `std(收益率, n)×sqrt(252)` | 风险度量、仓位缩放 | 历史波动率不等于未来 |

**实现要点**：

- 指标必须**只用当前及之前的数据**（`rolling` 天然满足，`shift(-1)` 一定错）；
- 周期不足时返回 `None`/`NaN`，策略里必须判空；
- 指标计算要可缓存（同一根 bar 不重复算），否则回测慢 10 倍；
- 指标值应可被 UI 画出（TradeSome 的 `IndicatorSeries` 同时供策略与图表使用）。

## 6. 回测：最容易被骗的地方

### 6.1 两种回测引擎

| 类型 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 向量化 | 用 pandas 一次性算完整列信号，再算收益 | 快、代码短 | 难处理仓位/资金/部分成交，容易引入未来函数 |
| 事件驱动 | 逐根 bar 推进，模拟订单→撮合→成交→持仓 | 贴近实盘、可复用同一套代码 | 慢一些、代码多 |

**做软件要用事件驱动**：回测、模拟盘、实盘共用同一套 `Strategy` 与 `Broker` 接口，只替换"时间源"和"撮合器"。这是"回测即实盘"的关键。

### 6.2 事件驱动回测的时序（必须严格执行）

```
for bar in bars:
    1. 用 bar 更新行情、计算指标（只能看到 bar 及之前）
    2. 撮合上一根 bar 产生的挂单（用当前 bar 的价格）
    3. 更新持仓市值、记录净值
    4. 调用 strategy.on_bar(bar) → 可能产生新订单
    5. 订单进入下一根 bar 的待撮合队列
```

**为什么订单要下一根 bar 才成交？** 因为 `on_bar` 收盘时才拿到 `close`，不可能用同一个 `close` 成交。真实做法是"收盘决策、次日开盘成交"，或"收盘价 + 滑点"近似。两种都可以，但必须写清楚。

### 6.3 回测的六大陷阱

| 陷阱 | 表现 | 防范 |
|---|---|---|
| **未来函数** | 回测逆天，实盘拉胯 | 数据切片只给到当前 bar；禁止 `shift(-1)`、`iloc[i+1]`；代码审查 |
| **幸存者偏差** | 用今天的成分股回测 5 年前 | 使用历史成分股/退市股票；或明确声明局限 |
| **过拟合** | 参数调到小数点后两位才好看 | 样本外验证、walk-forward、参数平台检验、限制参数个数 |
| **成本忽略** | 不算佣金印花税滑点 | 成本模型必须与真实一致；报告单列成本 |
| **数据窥探** | 先看答案再选策略 | 先写规则后看数据；固定测试集只跑一次 |
| **流动性/容量** | 假设无限成交 | 成交量占比上限（如不超过当日成交量的 5%）、涨跌停不可成交 |

### 6.4 成本模型怎么写

```
买入成本 = 成交额 × 佣金率（最低 5 元）+ 成交额 × 过户费率
卖出成本 = 成交额 × 佣金率（最低 5 元）+ 成交额 × 过户费率 + 成交额 × 印花税率
滑点     = 成交价 × 滑点率（买加、卖减），或 固定跳数
冲击成本 = k × sqrt(下单量 / 日均成交量)   （大资金才需要）
```

**回测报告必须回答**：扣费前收益多少、扣费后多少、成本占毛利多少。如果成本吃掉 50% 以上，这个策略在实盘基本没戏。

### 6.5 回测结果的可信度分级

- ★☆☆ 单标的、单参数、全样本回测 → 只能证明"代码能跑"；
- ★★☆ 样本外验证 + 成本模型 + 多标的 → 有参考价值；
- ★★★ 滚动窗口 + 参数敏感性 + 不同市场阶段 + 模拟盘 → 可以考虑小资金实盘。

## 7. 绩效指标：怎么判断一个策略是好是坏

假设日频净值序列为 `equity[0..N]`，年化交易日 `252`。

| 指标 | 公式 | 怎么读 |
|---|---|---|
| 累计收益 | `equity[-1]/equity[0] − 1` | 总赚了多少（要和回撤一起看） |
| 年化收益 | `(1+累计收益)^(252/N) − 1` | 换算成年，便于比较 |
| 年化波动率 | `std(日收益) × sqrt(252)` | 波动越大，越难拿住 |
| 夏普比率 | `(年化收益 − 无风险利率) / 年化波动率` | >1 不错，>2 很好，>3 要怀疑过拟合 |
| 索提诺比率 | `(年化收益 − 无风险利率) / 下行波动率` | 只惩罚下跌，更贴合体感 |
| 最大回撤 | `max(1 − equity/峰值)` | 最疼的时候亏多少，决定你敢不敢上 |
| 回撤持续期 | 从峰值到恢复最长天数 | 拿得住的时间成本 |
| 卡玛比率 | `年化收益 / |最大回撤|` | >1 算优秀，>3 极好 |
| 胜率 | 盈利交易数 / 总交易数 | 单独看没意义 |
| 盈亏比 | 平均盈利 / 平均亏损 | 和胜率一起看：期望 = 胜率×均盈 − 败率×均亏 |
| 盈利因子 | 总盈利 / 总亏损 | >1.5 较好 |
| 换手率 | 成交额 / 平均净值 | 高换手 = 高成本敏感 |
| 最大连亏 | 连续亏损次数 | 心理承受力测试 |

**三个必须一起看的组合**：

1. **年化收益 + 最大回撤**（收益是拿命换的，回撤就是那条命）；
2. **夏普 + 换手率**（高夏普 + 高换手，多半是成本没算够）；
3. **胜率 + 盈亏比**（决定期望值，也决定你能否执行）。

**一个反直觉的事实**：十年十倍、最大回撤 60% 的策略，大多数人拿不住；年化 15%、回撤 8% 的策略反而更容易被长期执行。**可执行性也是绩效的一部分。**

## 8. 风控与资金管理：活下来的学问

### 8.1 先定义"一笔交易最多亏多少"

最常用的框架是 **R 倍数**：

```
R = 单笔允许亏损金额 = 账户净值 × 单笔风险比例（如 1%）
仓位股数 = R / (入场价 − 止损价)
```

例：账户 10 万，单笔风险 1% = 1000 元；入场 20 元，止损 19 元（每股亏 1 元）→ 买 1000 股（2 万元，20% 仓位）。

这样无论标的波动多大，**每笔最大亏损都是 1000 元**，风险被标准化了。

### 8.2 仓位管理方法对比

| 方法 | 公式 | 特点 |
|---|---|---|
| 固定金额 | 每笔买 2 万 | 简单，但风险随波动变化 |
| 固定比例 | 每笔买净值的 20% | 简单，回撤大时自动减仓 |
| 等风险（ATR） | `仓位 = 风险预算 / (2×ATR)` | 波动大的标的自动少买，推荐 |
| 凯利公式 | `f* = (p·b − q)/b` | 理论最优增长，但参数估计误差大，**实盘用半凯利或 1/4 凯利** |
| 波动率目标 | `仓位 ∝ 目标波动率 / 实际波动率` | 组合层面控制波动，机构常用 |
| 风险平价 | 按风险贡献分配 | 多资产组合，避免单一资产主导风险 |

凯利公式例子：胜率 55%，盈亏比 2:1 → `f* = (0.55×2 − 0.45)/2 = 0.325`，即 32.5% 仓位；实际用半凯利 ≈ 16%。

### 8.3 必须有的六道风控闸门

1. **单笔风险上限**：一笔最多亏净值的 1%–2%；
2. **单标的上限**：单只股票不超过总资产的 20%–30%；
3. **总仓位上限**：永不满仓，留 20%–30% 现金（知乎文章也强调"留 30% 现金应对极端行情"）；
4. **当日亏损熔断**：当日亏损达 3% 停止开新仓；达 5% 全部平仓并停手；
5. **回撤熔断**：净值从峰值回撤 15% 降半仓，20% 停止交易，人工复核；
6. **异常保护**：行情断流、数据异常、下单失败率过高时自动停机（kill switch）。

### 8.4 风险不是只有价格

- **流动性风险**：想卖卖不掉（跌停、停牌）；
- **集中度风险**：全仓一个行业；
- **模型风险**：策略假设失效；
- **操作风险**：手滑下错单、程序 bug 重复下单（必须有幂等键与订单频率限制）；
- **对手方/技术风险**：券商接口断线、本地断电（要有状态恢复与对账）。

## 9. 从回测到实盘：最后一段路最贵

### 9.1 三步走

1. **模拟盘（1–2 个月）**：实时行情 + 虚拟资金，检验"回测→实盘"的偏差（滑点、成交率、延迟）；
2. **小资金实盘（3–6 个月）**：1–2 万元，感受真实心理压力与真实成本；
3. **逐步加仓**：稳定盈利半年以上再增加资金，永远不满仓单票。

### 9.2 回测与实盘的差异来源

| 差异 | 说明 | 缓解 |
|---|---|---|
| 成交价 | 回测用收盘价，实盘可能滑点 | 加滑点模型；用限价单 |
| 成交率 | 回测假设必成交，实盘可能排队 | 涨跌停/流动性约束；记录未成交 |
| 延迟 | 信号→下单有秒级延迟 | 本地计算、预连接、异步下单 |
| 数据 | 实盘收到的是 tick/快照，回测是 bar | 统一到 bar 收盘决策 |
| 停牌/除权 | 实盘会真实遇到 | 数据质量校验 + 复权处理 |
| 心理 | 回撤时手动干预 | 纪律 + 自动执行 + 不看盘 |

### 9.3 实盘系统的必备能力

- **状态持久化**：程序崩溃重启后能恢复持仓、挂单、策略状态；
- **对账**：本地持仓 vs 券商持仓，不一致要报警并停止交易；
- **幂等**：同一信号重复触发不能重复下单（客户端订单号 + 去重表）；
- **审计日志**：每个决策、每笔订单、每次风控拦截都要留痕，可回溯；
- **熔断开关**：一键停止所有策略并撤单；
- **监控告警**：进程存活、行情延迟、下单失败率、当日盈亏。

**设计原则**（TradeSome 严格遵循）：

1. **依赖倒置**：内核不 import 任何外层；数据/券商/存储都是接口 + 适配器；
2. **单一职责**：一个模块只做一件事，改撮合不影响 UI，改 UI 不影响策略；
3. **事件驱动**：模块间通过事件总线通信，不直接互调；
4. **可测试**：每个模块都能脱离 UI 单测（回测引擎用固定数据即可验证）；
5. **可观测**：关键路径有结构化日志与审计表。

### 11.1 六个月路线（个人实践版）

| 阶段 | 时间 | 内容 | 产出 |
|---|---|---|---|
| 1. 认知与 Python | 第 1 月 | 变量/函数/类/pandas/numpy | 能读 CSV、算均线、画图 |
| 2. 数据 | 第 2 月 | 拉日线、复权、清洗、存 SQLite | 一个可复用的数据脚本 |
| 3. 策略与回测 | 第 3 月 | 双均线/布林带/网格，事件驱动回测 | 能跑出净值曲线与指标 |
| 4. 风控 | 第 4 月 | 仓位、止损、熔断、成本模型 | 回测报告含成本与回撤 |
| 5. 模拟盘 | 第 5 月 | 实时行情、模拟撮合、日志 | 连续跑 1 个月不崩 |
| 6. 小资金实盘 | 第 6 月 | 券商接口、对账、告警 | 真实成交记录与复盘 |

### 11.2 常见问题

**Q：需要学机器学习吗？**
A：不必须。先做好数据+规则+风控，收益的 80% 来自这三块。ML 是加分项，不是入场券。

**Q：多少资金可以开始？**
A：模拟盘零成本；实盘建议 1–2 万起步（注意最低 5 元佣金会显著抬高小资金成本）。

**Q：为什么我的回测年化 300%？**
A：大概率有未来函数、没算成本、用了未来成分股，或者过拟合。先怀疑自己。

**Q：策略多久失效？**
A：没有定数。简单趋势策略可能几年，高频套利可能几周。要持续监控"实盘 vs 回测"的偏离。

**Q：要不要用现成框架（backtrader/vnpy/qlib）？**
A：学习阶段可以用，理解事件驱动后建议自己写一遍核心引擎（几百行）， controllability 更强。本项目就是自研轻量引擎。

**Q：程序化交易合规吗？**
A：个人通过券商官方接口（QMT/Ptrade）交易是合规的；不得使用破解接口、不得操纵市场、遵守交易所程序化交易报备要求。数据使用要遵守数据源条款。
