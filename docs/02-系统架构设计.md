# TradeSome 系统架构设计

> 一句话：**六边形架构（端口—适配器）+ 事件驱动内核 + 单一组合根**。
> 目标不是"分层好看"，而是让"换数据源、换券商、换策略、换界面"这四件事互不影响。

---

## 1. 架构风格与原则

| 原则 | 落地方式 |
|---|---|
| 依赖倒置 | 内核不 import 外层；`data/ports.py`、`execution/ports.py` 定义协议，适配器实现 |
| 单一职责 | 一个文件一个主题；撮合、成本、指标、会计分开 |
| 显式依赖 | 所有依赖通过构造函数注入，由 `app/container.py` 统一装配，禁止模块级单例 |
| 事件驱动 | 模块间通过 `EventBus` 发布/订阅，不直接互调（UI 只订阅事件，不反调引擎） |
| 不可变数据 | `Bar`、`Fill`、`Signal` 等用 `frozen dataclass`，避免跨线程共享可变状态 |
| 失败隔离 | 策略/插件异常被捕获并转为事件；一个策略崩溃不影响引擎与其他策略 |
| 可测试 | 每个模块都能在不启动 UI 的情况下单测 |

```
│    bootstrap / container / services                                  │
└───────────────▲─────────────────────────────────▲───────────────────┘
                │                                 │
┌───────────────┴───────────┐   ┌─────────────────┴───────────────────┐
│ L2 领域服务                │   │ L2 适配器                          │
│  strategy / backtest /     │   │  data/providers / execution/       │
│  risk / portfolio          │   │  gateway / trading / persistence / │
│                            │   │  security                          │
└───────────────▲───────────┘   └─────────────────▲───────────────────┘
                │                                 │
┌───────────────┴─────────────────────────────────┴───────────────────┐
│ L1 内核  tradesome/core/*                                            │
│    types / errors / bus / events / clock / config / logging / ids /   │
│    money / instruments / calendar                                     │
└──────────────────────────────────────────────────────────────────────┘
```

**硬性依赖规则**（由 `tests/unit/test_architecture.py` 静态扫描 import 验证）：

1. `core` 只能 import 标准库与 `core` 自身；
2. `strategy` / `backtest` / `risk` / `portfolio` 可 import `core`，**不得** import `ui`、`app`、`persistence`；
3. `data`、`execution`、`persistence`、`security` 可 import `core`，不得 import `ui`、`app`；
4. `gateway` 只依赖 `core`（协议与网关实现），**不依赖** `trading`/`app`/`ui`；
   `trading` 可依赖 `core`、`execution`、`portfolio`、`strategy`，不得 import `ui`、`app`；
5. `app` 可 import 所有下层；`ui` 只能 import `core`、`app`、`ui`；
6. 任何模块不得 import `tkinter`，除 `ui` 之外；
7. 任何模块不得在 import 时产生副作用（建库、读配置、起线程）。

## 4. 关键流程

### 4.1 启动序列

```
__main__.main()
  → 解析参数（--demo / --safe-mode / --reset-ui / --log-level）
  → bootstrap.bootstrap()
      1. 解析 Paths（APP_ROOT/var，可用 TRADESOME_HOME 覆盖）
      2. 初始化日志（控制台 + var/logs/tradesome.log，10MB×3 轮转）
      3. 加载/创建 settings.json（失败则用默认值并备份坏文件）
      4. 打开 SQLite（WAL），执行迁移（幂等）
      5. 构造 Container（仓储、总线、服务、风控、券商）
      6. 首次运行检测（settings.first_run）→ 标记
  → ui.shell.Shell(container).run()
```

任何一步失败：写日志 → 弹出可读错误对话框（含日志路径）→ 退出码 1，不留下半初始化状态。

### 4.2 回测流程（时序）

```
UI 页面 ──run(config)──► BacktestService
                          │ 1. 校验参数（日期、资金、标的）
                          │ 2. 读 bar（BarRepository → 缓存）
                          │ 3. 构造 Strategy 实例（registry）
                          │ 4. 起后台线程 → BacktestEngine.run()
                          │      每 N 根 bar 发 BacktestProgress 事件
                          ▼
                    BacktestResult
                          │ 5. 落库（backtest_runs）
                          │ 6. 发 BacktestFinished 事件
UI 页面 ◄──事件── EventBus（主线程轮询队列后分发）
```

- UI 线程通过 `EventBus.drain()`（`after(50ms)` 轮询）消费事件，**回调永远在主线程执行**；
- 取消：`BacktestService.cancel()` 设置 `threading.Event`，引擎在每根 bar 检查并提前返回。

### 4.3 模拟实盘流程

```
LiveService.start(config)
  → 构造 Strategy + PaperBroker + RiskManager + SimulatedClock
  → 线程：LiveEngine.run()
       for bar in replay_queue:
           clock.advance_to(bar.dt)
           broker.on_bar(bar)          # 撮合上一轮挂单
           account.mark_to_market(...)
           strategy.on_bar(ctx, bar)   # 产生订单
           router.submit(order)        # 风控 → 券商 → 审计
           publish(LiveTick)           # 每根 bar 一次快照
           sleep(interval / speed)
  → stop(): 撤单、落库、发 LiveStopped
```

### 4.4 实盘流程

```
LiveTradePage 解锁 → LiveTradeService.start_session()
  → create_gateway("sim" | "qmt")           # sim 是本地演练柜台，qmt 直连 miniQMT
  → Gateway.start()                          # 令牌握手、心跳、断线重连
  → Account + LiveBroker + RiskManager + OrderRouter
  → 3 秒同步线程：query_account / query_positions / query_orders
       → oms.reconcile() 与本地状态比对 → 差异写入 live_events
  → 回报事件：gateway.order/trade → OrderManager.apply_update/apply_trade
       → 落库 orders/fills → 发 ORDER_UPDATED → UI 刷新
  → stop_session(): cancel_all → gateway.stop() → 落库 → LIVE_TRADE_STOPPED
```

关键约束：`gateway` 只讲协议；`trading` 只做状态与适配；服务层持有会话与线程；UI 只读快照与下单。
断线时在场委托标记 `UNKNOWN`，重连后对账，不猜测成交与否。

### 4.5 订单生命周期

```
策略 ctx.buy()
  → OrderRequest（client_id 幂等键）
  → OrderRouter.submit()
       ├─ 幂等检查（重复 client_id 直接返回原订单）
       ├─ 交易规则校验（手数/价格/时段/标的存在）
       ├─ RiskManager.pre_trade()  ──拒绝──► REJECTED + 审计 + 事件
       ├─ Broker.submit()          ──拒单──► REJECTED + 审计 + 事件
       └─ ACCEPTED/SUBMITTED
  → 撮合 → Fill → Account.apply_fill() → 审计 + OrderFilled 事件
```

### 4.6 策略加载

```
registry.discover()
  ├─ 内置：import tradesome.strategy.builtin.*，读 __strategy__ 元数据
  └─ 用户：扫描 var/strategies/*.py
       ├─ sandbox.check_source()  AST 扫描（禁止 import 危险模块/危险调用）
       ├─ importlib 以唯一模块名加载
       ├─ 必须暴露 `STRATEGY` 类（Strategy 子类）
       └─ 失败：记录错误，UI 显示"该策略加载失败 + 原因"，不影响其他策略
```

## 5. 并发模型

| 线程 | 职责 | 约束 |
|---|---|---|
| 主线程（Tk） | 所有 UI 绘制、事件分发、用户交互 | 禁止阻塞 > 50ms；禁止直接做 IO 密集操作 |
| 回测线程 | `BacktestEngine.run()` | 只写自己的结果对象，通过队列发事件 |
| 模拟盘线程 | `LiveEngine.run()` | 持有 broker/account 锁；快照用不可变对象发布 |
| 实盘同步线程 | `LiveTradeService._sync_loop()` | 每 3 秒查询柜台；写库走仓储锁；异常只记日志并置 last_error |
| 柜台回调 | `QmtGateway` / `SimGateway` 的回调 | 只翻译成网关事件并投递，不做 UI 与长耗时 IO |
| 日志/DB | SQLite 连接每线程独立（`check_same_thread=False` + 锁） | 写事务短小，避免长事务阻塞 UI |

**线程安全规则**：

1. 事件总线内部用 `RLock`；订阅者回调在**发布线程**执行，UI 订阅者必须先入队；
2. `Account`、`PaperBroker` 的公开方法加锁；
3. `Bar`/`Fill`/`Order`（对外快照）不可变，跨线程传递安全；
4. 后台线程异常必须捕获并 `publish(ErrorOccurred)`，禁止静默死亡。

## 6. 错误处理策略

| 层 | 策略 |
|---|---|
| 内核 | 抛领域异常（`TradeSomeError` 子类），消息含"发生了什么 + 建议动作" |
| 服务 | 捕获→转 `ServiceResult(ok, message, data)`，或转事件；不吞异常 |
| 引擎 | 单根 bar/单策略异常隔离，记录并继续；连续 N 次异常则中止 |
| UI | 统一 `ErrorDialog`，显示中文消息 + "查看日志"按钮；不弹 Python traceback |

异常体系（`core/errors.py`）：

```
TradeSomeError
├─ ConfigError
├─ DataError
│  └─ DataQualityError(issues)
├─ StrategyError
│  └─ StrategyLoadError
├─ BacktestError
├─ RiskRejected(rule_id, detail)
├─ ExecutionError
├─ PersistenceError
└─ SecurityError
```

## 7. 配置与环境

| 来源 | 优先级 | 说明 |
|---|---|---|
| 代码默认值 | 最低 | `core/config.py` 的 dataclass 默认值 |
| `var/settings.json` | 中 | 用户设置，原子写（临时文件+替换） |
| 环境变量 | 高 | `TRADESOME_HOME`、`TRADESOME_LOG_LEVEL` |
| 命令行参数 | 最高 | `--demo`、`--safe-mode`、`--reset-ui`、`--log-level` |

配置文件损坏时：备份为 `settings.json.bad-<ts>` → 用默认值启动 → UI 提示。

## 9. 质量属性权衡

| 权衡 | 选择 | 代价 | 理由 |
|---|---|---|---|
| 性能 vs 纯度 | 指标预计算全量数组，按索引暴露 | 内存 ×1.5 | 万根 bar 内无感，策略代码更简单 |
| 安全 vs 扩展性 | 用户策略 AST 白名单 | 无法做任意 IO | 桌面软件不应执行任意代码 |
| 简单 vs 通用 | 只做单账户、单币种 | 不支持多账户 | 个人用户场景 |
| 实时 vs 简单 | 模拟盘用 bar 回放而非 tick | 与真实成交有差异 | 与回测同构，教学价值更高 |
