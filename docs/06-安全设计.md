# TradeSome 安全设计

> 一句话：**本地软件，最大威胁不是黑客，而是"密钥明文落盘、路径穿越、误删数据、策略代码乱来、导出文件带毒"。**
> 本文件给出威胁模型与逐项对策；每条对策都能在代码里找到落点。

---

## 1. 资产与信任边界

| 资产 | 位置 | 价值 | 泄露后果 |
|---|---|---|---|
| API Key / 令牌 | `var/secrets.dat` | 高 | 他人可冒用额度 |
| 行情与回测数据 | `var/tradesome.db` | 中 | 研究泄露（不致命） |
| 用户策略源码 | `var/strategies/*.py` | 中 | 思路泄露 |
| 订单与审计日志 | DB `audit_log` / `orders` | 中 | 交易行为画像 |
| 配置文件 | `var/settings.json` | 低 | 偏好泄露 |

**信任边界**：
- 进程内：代码可信（我们自己写的），**用户策略源码不可信**（可能从网上抄来）；
- 文件系统：`var/` 与 `doc/`/`exports/` 可写，其余只读；
- 网络：**默认无出站请求**。任何"联网"能力必须由用户显式配置并提示。

## 2. 威胁模型（简化 STRIDE）

| 威胁 | 场景 | 影响 | 对策（编号见 §3） |
|---|---|---|---|
| 信息泄露 | 密钥写入日志/崩溃转储/明文配置 | 高 | S1 S2 S6 |
| 篡改 | 用户策略读文件、改数据库 | 高 | S3 S4 |
| 抵赖 | 误操作后无法追溯 | 中 | S5 |
| 拒绝服务 | 策略死循环卡死 UI | 中 | S7 |
| 权限提升 | 策略代码执行系统命令 | 高 | S3 |
| 路径穿越 | 导入 CSV 时 `../../windows/system32` | 高 | S4 |
| 公式注入 | 导出 CSV 被 Excel 执行 `=cmd` | 中 | S8 |
| 供应链 | 引入被投毒的第三方包 | 高 | S9 |

**不在威胁模型内**：物理接触、内存取证、操作系统级恶意软件、多用户并发（单机单用户）。

## 3. 安全控制

### S1 密钥加密（`security/vault.py`）

- Windows 优先：`CryptProtectData`（DPAPI，当前用户作用域，`CRYPTPROTECT_UI_FORBIDDEN`）；
- 存储格式：`{"v":1,"mode":"dpapi","items":{"key":{"iv":"","data":""}}}`，整体 base64；
- 非 Windows 或 DPAPI 失败：`mode:"fallback"`，PBKDF2-HMAC-SHA256(机器标识 + 随机盐, 200k 次) 派生密钥 + HMAC 校验；UI 明确提示"弱保护"；
- `get()` 返回的明文**只存在于内存**，不写日志、不进事件负载；
- 文件权限：创建后尝试 `icacls <file> /inheritance:r /grant:r %USERNAME%:F`，失败仅告警。

### S2 日志与界面脱敏（`security/redaction.py`）

- 日志 Filter 正则替换：`(api[_-]?key|token|secret|password|authorization)\s*[:=]\s*(\S+)` → `\1=***`；
- `mask_for_ui(v)`：长度 ≤ 8 显示 `****`；否则前 3 + `****` + 后 4（`sk-****abcd`）；
- 异常堆栈只在 DEBUG 级别写文件，UI 永不展示 traceback。

### S3 用户策略沙箱（`strategy/sandbox.py`）

- 保存前 + 加载前各扫一次 AST；
- 拒绝危险 import / 调用 / 逃逸属性（清单见 `docs/05` §6）；
- 加载失败 → `StrategyLoadError`，UI 显示"策略 X 加载失败：第 N 行使用了禁止的 xxx"；
- **不追求绝对隔离**（同进程 Python 无法做到），定位是"防误用与明显恶意"，配合"无网络、无真实资金"降低影响面；
- 未来若要强隔离：子进程 + 受限 token + Job Object（ADR-006 记录为未采纳）。

### S4 输入与路径校验（`security/validation.py`）

| 输入 | 规则 |
|---|---|
| 标的代码 | `^[0-9]{6}\.(SH|SZ|BJ)$`，长度固定 |
| 日期 | `date.fromisoformat`，范围 1990-01-01 ~ 2100-12-31，`start <= end` |
| 数值参数 | 有限浮点（拒绝 `nan`/`inf`），在 `ParamSpec` 范围内 |
| 文件路径 | `safe_join(base, *parts)`：拒绝绝对路径、盘符、`..`、符号链接逃逸；`resolve()` 后必须仍在 base 下 |
| 文件名 | `sanitize_filename`：去除 `<>:"/\|?*` 与控制字符，长度 ≤ 120 |
| SQL | **全部参数化**，禁止 f-string 拼接；表名/列名来自白名单常量 |
| CSV 导入 | 单文件 ≤ 100MB；行数 ≤ 2,000,000；超限拒绝并提示 |

### S5 审计（`persistence/repositories.AuditRepository`）

记录（时间、类别、动作、详情、严重级）：
`strategy.load` / `strategy.save` / `strategy.delete`、`params.change`、`backtest.run`、`order.submit` / `order.reject` / `order.fill`、`risk.rule_change` / `risk.trip` / `risk.reset`、`data.import` / `data.delete`、`secret.write` / `secret.delete`、`config.change`、`app.start` / `app.stop`，以及实盘：`live/start` / `live/stop` / `live/emergency` / `live/confirm_order`。

- 只追加；UI 只读；无删除入口；
- 单条 `detail` ≤ 2000 字符，超出截断；
- 审计写入失败**不阻断**业务，但写 ERROR 日志并在状态栏红点提示。

### S6 内存与崩溃

- 不把密钥放进 `dataclass(repr=True)` 的字段（`repr=False`）；
- 全局异常钩子：`sys.excepthook` + `threading.excepthook` → 日志 + 友好弹窗，不打印密钥；
- 崩溃转储不落盘（避免包含内存明文）。

### S7 资源与拒绝服务

- 回测/实盘在后台线程，UI 不阻塞；
- 引擎每根 bar 检查 `cancel` 事件；
- 策略单次 `on_bar` 超过 2 秒 → 记录 WARN；连续 3 次 → 中止并提示"策略执行过慢"；
- 事件总线环形缓冲上限 500，防止无限增长；
- 日志轮转 10MB × 3。

### S8 导出安全

- CSV 导出时，任何以 `=`、`+`、`-`、`@`、`\t`、`\r` 开头的单元格前加单引号 `'`（防 Excel 公式注入）；
- HTML 报告：所有动态文本 `html.escape`；不引入外部 JS/CSS（离线、无 XSS 面）；
- 文件名使用 `sanitize_filename`。

### S9 依赖与供应链

- **零第三方依赖**（仅标准库）；`requirements.txt` 为空并注明原因；
- 若未来引入依赖：必须锁版本 + 记录哈希 + 在 ADR 说明；离线环境下需随包分发 wheel。

### S10 数据保护与备份

- "重置全部数据"前自动 `db.backup(var/backups/tradesome-<ts>.db)`；
- 删除标的需输入代码确认；
- 数据库不含密钥；`secrets.dat` 单独文件，可单独删除（删除后需重新录入）。

### S11 实盘交易安全（第二版新增）

实盘通道的信任边界是：**TradeSome（本机 GUI） ↔ xtquant ↔ 本机 miniQMT ↔ 券商柜台**。

| 控制 | 实现 |
|---|---|
| 默认关闭、启动即锁定 | `config.live.enabled` 默认 `False`；`LiveTradeService.arm()` 只在当前进程有效，重启后必须重新解锁 |
| 解锁需明确知情 | 实盘页勾选「已阅读风险」并输入确认词「实盘交易」；未解锁时所有下单入口禁用 |
| 下单二次确认 | 手动下单弹 `ConfirmModal`；确认动作写审计 `live/confirm_order`；自动交易本身需单独开关 |
| 只发限价单 | `allow_market_orders` 默认 `False`；即便开启，服务层也把市价转成保护价限价（±1%，不超过涨跌停） |
| 金额与频率上限 | 单笔 ≤ `max_order_value`（默认 5 万）、每日 ≤ `max_orders_per_day`（默认 200），超限直接抛 `TradingError`，不到网关 |
| 风控前置 | 复用同一套 `RiskManager` 8 条规则与熔断；拒单原因落审计与 `live_events` |
| 只连本机 | 网关只调用本机已登录的 miniQMT，不开放端口、不监听网络；目录与账号填错时连接直接失败 |
| 券商密码不落盘 | TradeSome 不保存券商账号密码，认证由 QMT 客户端完成；本软件只保存 `userdata_mini` 目录与资金账号 |
| 断线不猜成交 | 在场委托标 `UNKNOWN`；重连后 `oms.reconcile()` 对账，差异写 `live_events`；不自动重发订单 |
| 关闭软件先撤单 | `Shell._really_close()` 先 `emergency_stop("关闭软件")`，撤单并断开后才销毁窗口 |
| 全部留痕 | 连接、断开、下单、撤单、拒单、解锁、紧急停止、对账差异都写 `audit_log` / `live_events` |

**残余风险**：miniQMT 与券商柜台在信任边界之外，最终成交以券商为准；本软件不提供"保证不误单"的承诺，
只保证本地侧不绕过确认、不隐藏状态。相关测试：`tests/unit/test_gateway.py`（状态机/保护价）、
`tests/unit/test_qmt_gateway.py`（连接/下单/回报翻译/撤单）、`tests/unit/test_live_trade_service.py`（未解锁/超限/撤单）。

### S12 策略工坊的代码执行边界

- 策略档案只存 JSON（参数、模板名、三个风控阈值），**不存也不生成 Python 源码**；
- 运行时由 `strategy/profile.py` 动态构造 `ProfileStrategy`，模板类来自内置注册表，用户无法注入代码；
- 叠加层参数名统一加 `risk_` 前缀，避免覆盖模板参数（曾出现同名覆盖，见 docs/13 缺陷）；
- 删除档案只删数据库行，不影响内置策略与遗留 `.py` 文件；
- 手写 `.py` 仍走 AST 沙箱（import 白名单、禁文件/网络/反射）。

## 5. 合规与风险提示

- 首启弹窗与"帮助 → 风险声明"固定文案：

> 本软件仅用于学习与研究，**不构成投资建议**，**不接入真实资金**。历史回测不代表未来收益。股市有风险，入市需谨慎。

- 模拟盘界面常驻"模拟"角标，避免误认为真实交易；
- 不提供"保证收益""稳赚"类文案（代码审查项）。

## 6. 事件响应（个人软件版）

| 情况 | 处置 |
|---|---|
| 怀疑密钥泄露 | 设置页删除密钥 → 去服务商后台吊销 → 重新生成 |
| 数据库损坏 | 用 `var/backups/` 最近备份替换；日志定位损坏前的操作 |
| 策略行为异常 | 停用该策略（移动到 `var/strategies/_disabled/`）→ 查看审计与回测日志 |
| 软件无法启动 | 查看 `var/logs/tradesome.log` 最后 50 行；`--safe-mode` 以默认配置启动 |

## 7. 安全测试用例（对应 `tests/unit/test_security.py`）

1. vault：写入→读取往返一致；错误密钥读取失败；文件内容不含明文；
2. redaction：含 `api_key=abc123` 的日志行被替换；
3. validation：`../../etc/passwd`、`C:\Windows\system32`、`a\x00b` 均被拒绝；
4. sandbox：`import os`、`eval("1")`、`__import__("os")` 均被拒；
5. 导出：单元格 `=1+1` 变为 `'=1+1`；
6. 迁移：重复执行不报错、不重复建表。
