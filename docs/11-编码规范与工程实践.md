# TradeSome 编码规范与工程实践

> 规范的目的不是"好看"，而是：**新人 10 分钟能看懂一个文件；改一个模块不会碰坏另一个；review 时不用争论风格。**

---

## 1. 语言与兼容性

- Python 3.9+；不使用 3.10+ 语法（`match`、`X | Y` 运行时注解、`dataclass(slots=True)`）；
- 需要新式注解的文件首行加 `from __future__ import annotations`；
- 仅标准库；禁止 `pandas`、`numpy`、`matplotlib`、`requests`（`test_architecture.py` 会扫描）。

## 2. 文件结构（固定顺序）

```python
"""模块一句话职责。

设计说明（可选）：为什么这样切、与其他模块的边界。
"""
from __future__ import annotations

import 标准库                       # 按字母序
from 标准库 import ...

from tradesome.core.xxx import ...  # 本项目，按层级

__all__ = ["PublicClass", "public_func"]

常量 = ...

class/def ...
```

- 文件 ≤ 600 行，函数 ≤ 60 行，类 ≤ 400 行；
- 一个文件只放一个主题；同类小工具可放一起（如 `indicators.py`）；
- 禁止在模块顶层执行 IO、起线程、读配置。

## 3. 命名

| 对象 | 规则 | 例 |
|---|---|---|
| 模块/包 | 小写 + 下划线 | `paper_broker.py` |
| 类 | PascalCase | `BacktestEngine` |
| 异常 | `XxxError` | `DataQualityError` |
| 函数/变量 | 小写 + 下划线 | `compute_metrics` |
| 常量 | 全大写 | `MAX_VOLUME_RATIO` |
| 私有 | 前缀 `_` | `_match_pending` |
| 布尔 | `is_/has_/can_/should_` | `is_trading_day` |
| 回调 | `on_xxx` | `on_bar` |
| 数据库列 | 小写 + 下划线 | `filled_qty` |
| UI 控件变量 | 后缀表类型 | `run_btn`、`symbol_cb`、`equity_chart` |

**避免**：`data`、`info`、`temp`、`obj`、`handle` 这类无信息量的名字；单字母变量仅用于循环索引与坐标。

## 4. 类型与数据

- 公开函数必须标注参数与返回类型；
- 用 `Optional[X]` 而非 `X | None`（3.9 兼容）；
- 容器优先 `list/dict/tuple`，需要不可变时用 `tuple`/`frozen dataclass`；
- 金额 `float`，数量 `int`，时间 `datetime`（naive），ID `str`；
- 不用可变默认参数（`def f(x=[])` 禁止）；
- dataclass 用于数据载体，普通类用于有行为/生命周期的对象。

## 5. 异常

```python
# 好
raise DataError("该标的没有行情数据", detail=f"{symbol} 在 {start}~{end} 无记录",
                hint="请在数据中心同步真实行情，或导入 CSV"

# 坏
raise Exception("no data")
```

- 只抛 `TradeSomeError` 子类；第三方/标准库异常在边界处转换；
- 捕获要具体：`except (ValueError, KeyError) as exc:`，禁止裸 `except:`；
- 捕获后必须：记录日志 / 转事件 / 转返回值，三者之一；
- 用户可见消息：**发生了什么 + 为什么 + 下一步**，不含类名与堆栈。

## 6. 日志

```python
log = logging.getLogger(__name__)
log.debug("bar %s %s close=%.2f", symbol, dt, close)   # 惰性格式化
log.info("回测完成 run_id=%s 用时=%.2fs", run_id, sec)
log.warning("数据缺口 symbol=%s 缺口=%d", symbol, gaps)
log.error("回测失败 run_id=%s", run_id, exc_info=True)
```

- 用 `%s` 占位，不用 f-string（避免无谓求值）；
- 不打印密钥、完整用户路径、超长列表（> 20 项只打数量）；
- 每模块一个 logger，名字 = 模块 `__name__`；
- INFO 记录"业务里程碑"，DEBUG 记录"每根 bar/每单"。

## 7. 注释与文档

- 公开类/函数：docstring 说明"做什么/参数/返回/异常"，中文；
- 非显然的逻辑：行内注释说明**为什么**，不解释"是什么"；
- 复杂公式：注释给出公式与出处（如"夏普 = (年化-无风险)/年化波动"）；
- 禁止提交注释掉的死代码；临时调试用 `# TODO(name):` 并登记。

```python
def max_drawdown(equity: Sequence[float]) -> tuple[float, int]:
    """计算最大回撤与其持续天数。

    回撤 = 1 - equity / 历史峰值；返回 (最大回撤比例, 最长未创新高天数)。
    空序列返回 (0.0, 0)。
    """
```

## 8. 导入规则

- 绝对导入，禁止相对导入（`from .x import y`）；
- 顺序：`__future__` → 标准库 → 本项目 → 常量/`__all__`；
- 禁止循环导入：需要类型时用 `TYPE_CHECKING`；
- 延迟导入仅用于"启动慢的 UI 页面"与"可选能力"，并注释原因。

## 9. 线程与并发

- UI 只在主线程操作；
- 后台线程命名：`bt-<run_id>`、`live-<session_id>`；
- `daemon=True`，但停止时必须显式 `join(timeout)`；
- 共享状态加锁，锁的粒度到方法级；
- 线程内异常必须捕获并 `bus.publish("app.error", ...)`；
- 禁止在 `finally` 之外吞掉 `KeyboardInterrupt`/`SystemExit`。

## 10. 文件与路径

- 所有路径来自 `Paths` 对象，禁止硬编码 `C:\` 或 `./var`；
- 写文件用原子写：临时文件 + `os.replace`；
- 读写文本显式 `encoding="utf-8"`；
- 用户输入路径必须过 `safe_join`。

## 11. UI 代码规范

- 颜色/字体/间距只从 `theme` 取，禁止 `"#ff0000"` 硬编码；
- 页面类只做"组装 + 事件绑定 + 展示"，业务逻辑放 service；
- 控件命名 `xxx_btn/_lbl/_entry/_cb/_tree/_chart`；
- 布局优先 `grid`（带 `weight`），少用 `place`；
- 所有 `after` 定时器保存 id，页面销毁时 `after_cancel`；
- 长任务用 `Thread` + 事件回传，禁止 `time.sleep` 在 UI 线程。

## 12. 测试代码规范

- 测试名说人话：`test_buy_rejected_when_cash_insufficient`；
- 一个测试一个断言主题（可多个 assert，但同一主题）；
- 不依赖执行顺序、不共享可变夹具；
- 用 `self.assertRaises` 上下文管理器并检查 `code`；
- 测试中的魔法数要有注释或命名常量。

## 13. 提交规范（Git）

```
<type>(<scope>): <subject>

<body 可选：为什么>

<footer 可选：Refs #12>
```
`type ∈ {feat, fix, refactor, perf, docs, test, chore, style}`；
`scope` = 模块名（`backtest`、`ui/backtest`）。

示例：
```
feat(risk): 新增价格带校验，防止胖手指下单

限价偏离现价超过 10% 直接拒绝。阈值可在设置中调整。
```

## 14. 代码审查清单

- [ ] 是否遵守分层依赖（没有反向 import）？
- [ ] 是否引入第三方依赖？
- [ ] 是否有裸 `except` / 吞异常？
- [ ] 是否有硬编码路径、颜色、魔法阈值？
- [ ] SQL 是否参数化？路径是否校验？
- [ ] 新逻辑是否有对应测试（或已在测试计划登记）？
- [ ] 用户可见文案是否中文、可读、无术语裸奔？
- [ ] 长任务是否在后台线程、可取消？
- [ ] 是否更新了相关文档（契约/ADR）？
