# 14 · 实盘接入设计（A 股 · 原生 QMT）

> 版本 2.0 · 2026-11-08 · 对应代码：`tradesome/gateway/`、`tradesome/trading/`、
> `tradesome/app/services/live_trade_service.py`、`tradesome/ui/pages/live_trade.py`

## 1. 背景与目标

TradeSome 第一版只有回测与历史回放模拟盘。第二版加入 A 股实盘，要求：

- 真实可用：能把限价委托发到券商柜台，能收到成交回报，能查账户/持仓/委托/成交；
- 零新增依赖：软件本体仍是 **Python 3.9 + 标准库**，不安装 vnpy、不编译 C++ 扩展；
- 与模拟盘共用一套风控、费用、审计与界面语言，不出现"实盘专用"的第二套逻辑；
- 默认关闭、每次启动重新解锁、每笔二次确认、只发限价单；
- 券商密码不进入 TradeSome，只保存 miniQMT 目录与资金账号。

### 非目标

- 不做期货/期权/港股/美股；
- 不做行情订阅与高频交易（行情仍用本地日线 + 手工刷新现价）；
- 不承诺策略盈利，也不绕过券商柜台的风控与合规要求。

## 2. 关键约束与方案选择

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 内嵌 vnpy | `import vnpy` 跑 MainEngine | ✗ vnpy 4.x 要求 Python 3.10+，且各家柜台接口是 C++ 封装，与 3.9/零依赖冲突 |
| B. 自研 CTP/XTP 封装 | ctypes 调券商 DLL | ✗ 工作量大、无公开头文件、稳定性不可控 |
| C. 独立 vnpy 桥接进程 | 本机 TCP + 令牌 | 可用，但需要用户再装一套 Python 3.10 环境与 vnpy（第一版做法，已移除） |
| **D. 原生 xtquant** | 进程内调用 QMT 客户端自带的 `xtquant` | **采用**：`xtquant` 是纯 Python 包、随 miniQMT 分发，不需要 pip 安装，也不需要 vnpy |

设计上仍然沿用 vnpy 的 **Gateway → 回报事件 → OMS → 风控/路由** 分层；区别只是
网关直接落在本进程，而不是通过 TCP 桥接。这样既满足"不依赖 vnpy"，也保留了
可替换柜台（模拟柜台与 QMT 实现同一个 `BaseGateway`）。

### xtquant 的边界

- `xtquant` 由迅投 QMT/miniQMT 客户端安装目录提供，不在 PyPI；
- 交易前必须在本机启动并登录 miniQMT，且券商已开通 QMT 权限；
- 只支持限价/市价等柜台允许的委托类型；本软件只发限价（市价会先转保护价）；
- 回调在 xtquant 自己的线程到达，网关负责翻译与线程安全。

## 3. 总体架构

```text
┌──────────────────────────── UI（Tkinter）────────────────────────────┐
│ 实盘页 LiveTradePage：解锁 → 连接 → 账户/持仓/委托/成交 → 手动下单   │
└───────────────────────────────┬──────────────────────────────────────┘
                                │ 调用服务层（不直接碰柜台）
┌───────────────────────────────▼──────────────────────────────────────┐
│ LiveTradeService                                                     │
│  · start_session / stop_session / emergency_stop                     │
│  · place_order → OrderRouter（风控/幂等/T+1/审计）→ LiveBroker        │
│  · 3 秒同步线程：query_account / positions / orders + 对账           │
│  · 自动交易：交易日 14:55 跑一次日线策略                             │
└───────────────┬───────────────────────────────┬──────────────────────┘
                │                               │
      ┌─────────▼─────────┐          ┌──────────▼──────────┐
      │ LiveBroker        │          │ OrderManager（OMS） │
      │ 市价转保护价限价  │          │ 状态机/去重/对账    │
      └─────────┬─────────┘          └──────────▲──────────┘
                │ place_order/cancel             │ 回报事件
      ┌─────────▼─────────────────────────────────┴──────────┐
      │ BaseGateway                                          │
      │  ├─ SimGateway：本地撮合，用于演练                   │
      │  └─ QmtGateway：进程内调用 xtquant，连 miniQMT       │
      └───────────────────────────┬──────────────────────────┘
                                  │
                        miniQMT / 券商柜台
```

依赖方向：`ui → app → trading/gateway/risk/portfolio → core`。
`gateway` 只依赖 `core`；`trading` 不依赖 `ui/app`；`gateway` 不被 `app` 之外的层反向引用。

## 4. 模块设计

### 4.1 `tradesome/gateway/protocol.py`

网关与交易域之间的**数据契约**，与券商 SDK 无关：

- 冻结 dataclass：`AccountUpdate`、`PositionUpdate`、`OrderUpdate`、`TradeUpdate`、`TickUpdate`；
- 状态常量：`GW_CONNECTING / GW_CONNECTED / GW_DISCONNECTED / GW_ERROR`；
- 错误码：`E_AUTH`、`E_PROTOCOL`、`E_TIMEOUT`、`E_DISCONNECTED`、`E_GATEWAY`、`E_REJECTED`；
- JSON 报文辅助（`make_request/response/error/event`、`parse_message`）保留给录制、回放与自定义适配器；进程内网关直接构造数据类。

### 4.2 `tradesome/gateway/base.py`

```python
class BaseGateway(ABC):
    name: str
    def set_listener(self, listener: Listener) -> None: ...
    def start(self) -> None: ...
    def stop(self) -> None: ...
    def place_order(self, order: dict) -> str: ...
    def cancel(self, broker_order_id: str, symbol: str = "") -> bool: ...
    def cancel_all(self, symbol: str = "") -> int: ...
    def query_account(self) -> AccountUpdate: ...
    def query_positions(self) -> list[PositionUpdate]: ...
    def query_orders(self) -> list[OrderUpdate]: ...
```

`_emit(event, data)` 统一投递事件，单个监听器抛异常不会影响其它监听器。

### 4.3 `tradesome/gateway/sim.py` — 本地模拟柜台

- 买入冻结 `price*qty` + 估算费用；卖出校验可用数量；
- `force_fill(order_id, qty, price)` 注入部分/全部成交，成交价取**更优现价**（买 `min(委托价, 最新价)`，卖 `max(...)`）；
- T+1：当日买入 `available=0`，跨日恢复；
- `feed_tick(symbol, price, volume)` 更新最新价并撮合触及价格的挂单；
- 与 QMT 共用 `BaseGateway`，因此服务层、风控、审计、UI 完全一致。

### 4.4 `tradesome/gateway/qmt.py` — 迅投 QMT 原生网关

```python
class QmtGateway(BaseGateway):
    def __init__(self, path: str, account_id: str, account_type: str = "STOCK",
                 session_id: int | None = None, module=None,
                 connect_timeout: float = 10.0): ...
```

| 步骤 | 调用 | 失败处理 |
|---|---|---|
| 创建 | `XtQuantTrader(userdata_mini, session_id)` | 路径为空抛 `GatewayError` |
| 注册回调 | `register_callback(TradeSomeQmtCallback)` | 回调异常只记日志 |
| 启动 | `start()` | 异常向上抛 |
| 连接 | `connect()`，0 成功 | 返回非 0 抛「连接 miniQMT 失败（返回 n）」 |
| 订阅 | `subscribe(StockAccount(account_id, account_type))` | 返回非 0 抛「订阅资金账号失败」 |
| 下单 | `order_stock(account, code, 23/24, qty, FIX_PRICE, price, strategy, remark)` | 返回 ≤0 抛错 |
| 撤单 | `cancel_order_stock(account, int(order_id))` | 0 成功 |

- **回调翻译**：`on_stock_order/on_stock_trade/on_order_error/on_cancel_error/on_account_status/on_disconnected`；
- **状态映射**：48/49/50/51→`SUBMITTED`，52/55→`PARTIAL`，53/54→`CANCELLED`，56→`FILLED`，57→`REJECTED`，其它→`UNKNOWN`；
- **客户单号**：`order_remark` 存 `client_id[:24]`，同时网关维护 `broker_order_id → client_id`；
- **延迟导入**：`xtquant` 缺失时抛中文提示「请先安装并登录 QMT/miniQMT……无需 vnpy」；
- **测试注入**：`module=` 可传假模块，单测不需要安装 QMT；
- **不订阅行情**：QMT 交易不依赖 tick；最新价由本地日线/手工刷新提供，避免引入额外的行情线程。

### 4.5 `tradesome/trading/oms.py` — 订单管理

- `STATUS_MAP` 统一柜台状态；`ALLOWED` 显式迁移表，终止态不可再变；
- 双索引：`client_id` 与 `broker_order_id`；`get()` 先按本地 `order_id`，再按 client_id；
- `apply_update()`：先 client_id 匹配，再 broker_id；找不到且数量>0 时登记 `EXT-<broker_id>` 只读单；
- `apply_trade()`：按 `trade_id` 去重，生成 `BRK-<trade_id>` 成交；
- `mark_unknown()`：断线时把在场单标 `UNKNOWN`，等对账修正；
- `reconcile(remote)`：与柜台委托列表比对，输出差异文案。

### 4.6 `tradesome/trading/live_broker.py`

实现现有 `Broker` 协议，把 `submit/cancel` 转成网关调用：

- 限价单直接 `round_price`；
- 市价单按 `最新价 × (1 ± protect_pct)` 生成保护价，用 `tick_size` 取整，`protect_pct` 不超过涨跌幅；
- 未连接时抛 `TradingError`；柜台返回后 `order.evolve(status=SUBMITTED, broker_order_id=..., gateway=...)`。

### 4.7 `tradesome/trading/live_market.py`

给策略的只读行情视图：本地日线 + 最新价合成当日 bar；`latest/bars/history` 与回测接口保持一致，
策略代码不需要区分模拟盘与实盘。

### 4.8 `tradesome/app/services/live_trade_service.py`

| 方法 | 作用 |
|---|---|
| `arm() / disarm()` | 本次运行内解锁/上锁（每次启动都重置） |
| `start_session(gateway_kind, strategy_key, qmt_path, qmt_account, qmt_account_type, params, symbols, initial_cash, auto_trade)` | 建会话、建网关、建账户/风控/路由、落库 `sessions(mode='live')`、启动 3 秒同步线程 |
| `stop_session(reason)` | 先 `cancel_all`，再 `gateway.stop()`，结束会话、写审计 |
| `emergency_stop(reason)` | 撤单 + 停止 + 审计 `live/emergency` |
| `place_order(...)` | 校验解锁/连接/单笔限额/当日笔数 → `OrderRouter.submit` → 返回合并后的最新订单 |
| `cancel / cancel_all` | 撤单并落库 |
| `sync_now()` | 页面轮询触发的同步（账户/持仓/委托/对账） |
| `run_strategy_once()` | 跑一轮日线策略；成功后记录自动交易时间 |
| `positions() / orders() / trades() / account_snapshot() / risk_state()` | 给 UI 的只读视图 |

不变量：

1. 未启用、未解锁、无网关时绝不报价；
2. 所有委托经过 `OrderRouter` 的风控、幂等、T+1 与审计；
3. 单笔金额与当日笔数在发单前检查；
4. 成交与委托状态以柜台回报为准，本地不"猜"成交；
5. 断线时在场单标 `UNKNOWN`，恢复后对账；
6. 关闭软件先撤单、再停会话；
7. 会话、委托、成交、风控拦截全部落库/审计。

### 4.9 UI：`tradesome/ui/pages/live_trade.py`

自上而下：

1. **解锁卡**：未启用 → 「去设置」；未解锁 → 风险勾选 + 输入「实盘交易」；已解锁 → 绿色提示 + 立即上锁；
2. **连接卡**：柜台（模拟柜台 / 迅投 QMT）、`userdata_mini` 目录、资金账号、账号类型、策略、标的、模拟初始资金、连接/断开/紧急停止；
3. **KPI**：总资产、可用资金、持仓市值、浮动盈亏；
4. **手动下单**：标的、方向、数量、价格、刷新现价、提交（二次确认 + 审计）；
5. **持仓 / 委托 / 成交** 三张表；委托可撤销，`UNKNOWN` 显示「待确认」；
6. **自动交易**：开关、计划时间、立即跑一轮。

页面只调服务层，不 import 任何网关或 xtquant。

### 4.10 已移除的桥接进程

第一版曾有 `tools/vnpy_bridge.py` 与 `BridgeGateway`（本机 TCP + 令牌）。按"不依赖 vnpy"的要求
已删除，相关文档、测试与启动脚本同步移除；`gateway/protocol.py` 的报文辅助保留，用于录制回放
和将来接其它进程内/进程外的柜台适配器。

## 5. 订单生命周期

```text
策略/手动
   │ OrderRequest
   ▼
RiskManager（8 条规则）──拒──► REJECTED（原因入库/审计）
   │ 通过
   ▼
LiveBroker.submit ──► QmtGateway.place_order ──► 柜台
   │                                              │
   │ 本地先记 SUBMITTED                           │ on_stock_order(50)
   ▼                                              ▼
OrderManager.apply_update ◄────────────────── 回报 50/55/56/54/57
   │
   ├─ 成交回报 on_stock_trade → Fill(trade_id) → 落库、更新账户
   └─ 断线 → mark_unknown → 重连查委托 → reconcile
```

关键点：

- 柜台回报可能早于 `place_order()` 返回，`register()` 保留更高状态，不把已成交改回已报；
- 同一 `client_id` 幂等，网络重试不会重复下单；
- 废单（57）保留柜台 `status_msg` 作为 `reason`。

## 6. 对账与故障处理

| 场景 | 处理 |
|---|---|
| 连接断开 | 发 `GATEWAY_DISCONNECTED`，在场单标 `UNKNOWN`，界面提示；重连后查询委托对账 |
| 查询超时 | 保留上次快照，`last_error` 提示，不修改本地订单状态 |
| 柜台拒单 | `on_order_error` → `REJECTED`，原因展示在委托表 |
| 本地有、柜台无 | `reconcile` 输出差异；不自动删除本地记录，等人工确认 |
| 柜台有、本地无 | 登记 `EXT-<broker_id>` 只读单，避免"看不见的持仓/委托" |
| 程序崩溃 | 重启后 `UNKNOWN` 单仍需人工在券商端核对；软件不猜测成交 |

## 7. 账户与持仓同步

- 每 3 秒 `query_account + query_positions + query_orders`；
- `Account.sync_from_broker(cash, positions, frozen_cash, equity)` 覆盖本地快照，`equity` 以柜台总资产为准；
- 持仓现价优先用 `_prices[symbol]`（手工刷新/tick），否则用柜台市值反推；
- `data/live_events` 记录连接、断开、错误与关键动作，便于事后排查。

## 8. 自动交易（日线策略）

- 开关在设置/实盘页，默认关闭；
- 仅在交易日、`config.live.run_time`（默认 14:55）触发一次，`auto_done` 防重复；
- 用本地日线跑一轮 `on_bar`，产生的委托仍走 `OrderRouter` 与风控；
- 自动交易不会绕过解锁与二次确认配置：实盘页必须先解锁并保持连接。

## 9. 安全设计

| 风险 | 措施 |
|---|---|
| 误触真实下单 | 默认关闭；每次启动重新解锁；确认词「实盘交易」；每笔二次确认 |
| 巨额/高频误单 | 单笔上限（默认 5 万）、每日委托上限（默认 200）、8 条风控、熔断开关 |
| 市价滑点 | 只发限价；市价需显式开启并转保护价 |
| 密码泄露 | 不保存券商密码；只存 miniQMT 路径与资金账号；xtquant 由客户端认证 |
| 越权访问 | 只连本机已登录的 miniQMT；不开放端口；无网络监听 |
| 断线误判 | `UNKNOWN` + 对账；不自动重发 |
| 审计缺失 | `live/start|stop|emergency|confirm_order`、委托、成交、风控拦截全部落库 |

## 12. 部署与券商接入步骤

1. 在券商开通 QMT/miniQMT 权限，安装并登录 QMT 客户端（保持运行）；
2. 找到 `userdata_mini` 目录（例如 `D:\QMT\userdata_mini`）；
3. 打开 TradeSome → 设置 → 实盘：启用实盘、填目录与资金账号、选账号类型；
4. 实盘页：勾选风险 → 输入「实盘交易」解锁；
5. 柜台选「迅投 QMT」，确认目录/账号，点连接；
6. 先下一笔 100 股限价单验证：委托表出现「已报」，成交后持仓与账户更新；
7. 确认无误后再开启自动交易；关闭软件前会先撤单。

## 13. 已知限制

- 只有安装了 QMT/miniQMT 的 Windows 机器可用；macOS/Linux 不支持；
- 只做 A 股/ETF 限价单；不做期权、期货、港股；
- 行情不订阅 tick，现价需手工刷新或由日线推算，不适合日内高频；
- 未与真实券商做过端到端联调（无柜台环境），首次使用请用小单验证；
- 单账户、单进程；不支持多账户切换；
- 策略仍以日线为主，自动交易每天一次，不是日内交易系统；
- 本软件不提供投资建议，实盘盈亏由用户自行承担。
