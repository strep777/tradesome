# 策略工坊：可视化创建策略（参考 vnpy）

> 版本：1.0（2026-11-09）
> 目标读者：想写策略但不写代码的用户；维护策略子系统的开发者。
> 相关代码：`tradesome/strategy/profile.py`、`tradesome/strategy/registry.py`、`tradesome/app/services/strategy_service.py`、`tradesome/ui/widgets/strategy_wizard.py`、`tradesome/persistence/strategy_profiles.py`。

## 1. 背景与目标

TradeSome 最初把「自定义策略」做成了在实验室里编辑 Python 文件：写类、声明参数、保存到 `var/strategies`。这对会写代码的人是够用的，但对「想调一个均线策略」的用户来说门槛过高，而且把「文件」暴露成了一个必须理解的概念。

这次改造的目标只有一句话：**用户不再创建、编辑或管理任何文件，也能拥有自己的策略。**

参考对象是 vnpy 的 CTA 策略模型：一个策略类声明 `parameters`（可调参数）与 `variables`（运行状态），由引擎按生命周期调用 `on_init / on_start / on_bar / on_stop`，用户在界面上填参数即可运行。TradeSome 保留这套「模板 + 参数 + 生命周期」的心智模型，但把「策略类」改为由系统**根据一份档案动态生成**，用户只需要在向导里做选择。

### 非目标

- 不做任意 Python 代码执行，也不做代码生成给用户看。
- 不做图形化积木编程（拖拽节点、连线）。当前是「模板 + 参数 + 风控叠加层」，覆盖均线、布林、RSI、网格、动量、情绪六类常用思路。
- 不改变回测/模拟盘/实盘的下单链路：工坊生成的策略仍然通过 `StrategyContext → OrderRouter → Broker` 走同一套风控与审计。

## 2. 参考 vnpy 的哪些部分

vnpy 的 CTA 策略大致是：

```python
class DoubleMaStrategy(CtaTemplate):
    parameters = ["fast_window", "slow_window"]
    variables = ["fast_ma", "slow_ma"]

    def on_init(self): ...
    def on_start(self): ...
    def on_bar(self, bar): ...
    def on_stop(self): ...
```

对本项目有参考价值的是四点：

| vnpy 概念 | TradeSome 的对应物 | 说明 |
| --- | --- | --- |
| 策略类 + `parameters` 声明 | 内置模板 + `ParamSpec` | 参数由界面自动生成表单，不写 UI 代码 |
| 用户填 `setting` 字典 | 策略档案的 `params` / 叠加层 | 存在 SQLite，不落到 `.py` 文件 |
| 引擎调用生命周期 | `Strategy.on_start/on_bar/on_stop` | 已有实现，工坊生成类复用 |
| 一个策略实例一份状态 | 每个回测/会话 `create()` 新实例 | 避免共享状态 |

没有照搬的部分：

- vnpy 通过加载 `.py` 文件注册策略类；TradeSome 不加载用户文件，而是把档案编译成一个**进程内子类**。
- vnpy 的 CTA 引擎是独立进程；TradeSome 的策略在回测线程或模拟/实盘会话线程内运行，仍受统一风控约束。
- vnpy 允许策略直接调 `buy/sell`；TradeSome 的策略只能拿到 `StrategyContext`，市价单会被上层按风控规则拒绝或转保护价。

> 调研说明：本文写作时外部文档抓取接口返回 HTTP 402（账号/额度问题），无法在线引用 vnpy 原文。以上对照基于 vnpy 公开的 `CtaTemplate` 接口约定（`parameters` / `variables` / `on_init` / `on_start` / `on_bar` / `on_stop` / `buy` / `sell` / `load_bar`），未臆造其它 API。若后续需要逐条引用，可在网络可用时补充链接。

## 3. 用户视角的流程

1. 打开「策略库」，点右上角「新建策略」。
2. 填写策略名称（2–24 个字符）。
3. 选择模板（例如「双均线趋势 · 趋势」）。
4. 调整模板参数（快线、慢线、仓位等）。
5. 可选地设置三个风控叠加层：
   - 风控止损：收盘价相对持仓成本下跌超过该比例时清仓；0 关闭。
   - 风控止盈：上涨超过该比例时清仓；0 关闭。
   - 风控趋势均线：收盘价低于该均线时不允许开新仓；0 关闭。
6. 点「保存并可用」。策略立刻出现在策略库、回测、模拟盘、实盘的策略下拉框中。
7. 之后可以「编辑」改参数，或「删除」；历史回测与成交记录不受影响。

不需要输入文件名、不需要选目录、不需要写 import。

## 4. 数据模型

档案是一份纯 JSON，存于 `strategy_profiles` 表：

```json
{
  "profile_id": "9f2c1a7b04",
  "key": "custom_9f2c1a7b04",
  "name": "我的双均线",
  "template": "ma_cross",
  "params": {"fast": 5, "slow": 20, "weight": 0.25},
  "stop_loss_pct": 5.0,
  "take_profit_pct": 20.0,
  "trend_ma": 60,
  "created_at": "2026-11-09 18:00:00",
  "updated_at": "2026-11-09 18:00:00"
}
```

约束：

- `profile_id` 为 10 位十六进制；`key` 固定为 `custom_<profile_id>`。
- `name` 长度 2–24，不允许控制字符。
- `template` 必须是当前注册表中的非自定义策略。
- `params` 只允许模板声明的参数；值按 `ParamSpec` 强转与夹紧，未知键忽略。
- 三个叠加层的字段名在运行时是 `risk_stop_pct` / `risk_take_pct` / `risk_trend_ma`，避免与模板自带的 `stop_loss_pct`、`trend_ma` 等同名参数冲突；档案对外仍使用 `stop_loss_pct`、`take_profit_pct`、`trend_ma` 三个字段。

数据库迁移 v3：

```sql
CREATE TABLE strategy_profiles (
  profile_id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  template TEXT NOT NULL,
  spec_json TEXT NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE INDEX idx_strategy_profiles_updated ON strategy_profiles(updated_at);
```

`spec_json` 存完整快照，而不是把字段拆列。这样以后加字段（例如「最大持仓数」「调仓周期」）不需要再改表；代价是不能用 SQL 直接按参数筛选，当前没有这种需求。

## 5. 动态策略类

`make_profile_class(spec, base_cls)` 生成一个 `ProfileStrategy` 子类：

- 类属性 `profile_spec` / `base_cls` / `meta`，`meta.key = spec.key`。
- `__init__` 创建模板实例 `self._base`，把 `spec.params` 灌进去，再在 `self.p` 上叠加三个风控参数。
- `param_specs()` 返回「模板参数 + 三个叠加层」，界面据此生成表单。
- `bind(ctx)` 同时把上下文交给模板，保证模板里的 `history/position_of/buy/sell` 正常。
- `on_start` 把 `self._buy_allowed` 安装到 `ctx.buy_filter`：只拦截新开仓，不拦平仓与止损。
- `on_bar` 先算当前 bar 是否被趋势均线拦截，再调用模板 `on_bar`，最后检查止损/止盈。
- `configure(values)` 合并当前值后再写回模板，避免「只改一个参数，其它参数被默认值覆盖」。
- `reset` 同时重置模板状态，供回测复用。

生命周期与 vnpy 的对应关系：

| 阶段 | vnpy | TradeSome |
| --- | --- | --- |
| 初始化 | `on_init` | `Strategy.__init__` + `configure` |
| 启动 | `on_start` | `on_start`（安装买入过滤器） |
| 每根 K 线 | `on_bar` | `on_bar`（模板 + 叠加层） |
| 停止 | `on_stop` | `on_stop` + `reset` |

## 6. 服务层 API

`StrategyService` 新增：

| 方法 | 作用 |
| --- | --- |
| `load_profiles()` | 启动时从数据库恢复档案并注册；坏档案跳过、写日志 |
| `profiles()` | 全部档案（按更新时间倒序） |
| `template_choices()` | 可作为模板的内置策略，不含自定义策略 |
| `profile_spec(key)` | 取一份档案的 JSON |
| `validate_profile_payload(payload, profile_id=None)` | 只校验不保存，供界面预检 |
| `save_profile(payload, profile_id=None)` | 校验、注册、落库、审计；保留原 `created_at` |
| `delete_profile(profile_id)` | 注销动态类、删库、审计 |

`metas()/meta()` 对自定义策略额外返回 `is_profile / profile_id / template / parameters / overlays`。

注册表新增 `register_profile / unregister_profile / is_profile / profile_keys`。`create()` 对档案策略不再用默认值覆盖传入参数，只对模板参数做合并。

## 7. 界面

- 策略库右上角「新建策略」打开 `StrategyWizard`。
- 向导是模态卡片：标题栏可拖动，内容区可滚动，底部固定「取消 / 保存并可用」。
- 切换模板会重建参数表单，但保留已经填写的风控叠加层。
- 保存失败时在表单下方显示中文原因（例如「止损阈值需小于 50%」）。
- 实验室只保留「参数试跑」，顶部提示「要保存成自己的策略，去策略库 → 新建策略」；原来的「策略代码」页签已移除。
- 策略详情页对自定义策略显示「编辑」「删除」；内置策略只显示「用此策略回测」「在实验室调参」。

## 8. 安全与边界

- 档案是数据，不是代码：不 `eval`、不 `exec`、不写 `.py` 文件。
- 动态类只在进程内注册，随进程退出消失；下次启动由数据库重建。
- 旧的手写策略文件仍能被 `StrategyRegistry` 加载（兼容历史用户），但 UI 不再提供创建入口。
- 风控叠加层只负责「清仓」与「禁止开新仓」，不绕过 `OrderRouter` 的仓位、频率、价格偏离、熔断等规则。
- 删除档案不会删除历史会话、订单、成交、回测记录。

## 9. 测试

`tests/unit/test_strategy_profile.py`（12 个用例）：

- 校验：名称长度、模板存在、禁止基于自定义策略再套模板、叠加层边界、参数字符串强转。
- 动态策略：meta 与参数、趋势过滤拦截买入、止损触发 `close`、止盈触发 `close`。
- 服务：保存→出现在注册表→`create` 保留参数→删除；重启后仍在；编辑保持 `profile_id`；模板列表不含自定义策略。

另外全量测试覆盖注册表、风控、回测与 UI 冒烟；向导本身由截图与手工冒烟验证。

## 10. 已知限制与后续

- 只支持「单模板 + 三个风控层」，不能组合多个模板，也不能自定义指标。
- 不支持分批建仓、移动止损、按波动率调仓等更复杂的退出逻辑。
- 参数只支持标量（int/float/bool/str/choice），不支持列表或嵌套结构。
- 档案不区分账户；同一份档案可用于模拟盘和实盘，实盘仍受「只发限价、单笔上限、每日笔数」约束。
- 后续若要做「图形化积木」，可以在本模型上增加 `blocks` 字段，让动态类按块解释；不需要推翻现有档案格式。
