# 16 新手引导与自由组合策略设计

> 本文覆盖第三版的两个增强：**用户可以从零组合出一条新策略**（不再只是改内置模板参数），
> 以及**新手引导与操作教学**（首次启动、跨页引导、每页「本页怎么用」、帮助页教程）。
>
> 状态：已实现（2026-11-09）。相关代码：`strategy/rules.py`、`ui/widgets/strategy_wizard.py`、
> `ui/widgets/tour.py`、`ui/pages/help.py`、`ui/pages/base.py`。

---

## 1. 为什么要做

上一版的「策略工坊」只能选一个内置模板、改它的参数。用户能保存自己的策略，但**策略的结构**
仍然是内置的：均线交叉的退出逻辑、布林的出场规则都写死了。用户说「用户可以新建新的策略方式，
而不是在已有的上面修改」，指的就是这一层——他要能组合出自己的入场/出场逻辑，而不是只调参数。

第二件事：页面虽有空状态文案和帮助页，但第一次打开的人仍要猜「先点哪里、下一步去哪」。
知识文档和 FAQ 是查的，不是教的。需要**手把手、可跳过、可重看**的引导。

### 目标

1. 用户在策略向导里选「自由组合」，用下拉框搭出 1–4 个入场条件 + 一组退出规则，保存后即可回测/模拟/实盘；
2. 全流程仍然零文件、零用户代码；档案是 JSON；
3. 第一次启动给出「3 分钟上手」入口，可跨页高亮关键控件，能上一步/下一步/跳过；
4. 每页有「本页怎么用」按钮，帮助页有教程中心，随时可重看；
5. 引导完成状态写入数据库，不再每次弹。

### 非目标

- 不做任意 Python 代码编辑、不做指标公式解析器（避免变成一门脚本语言）；
- 不做多标的配对/套利组合；组合策略仍按标的独立运行；
- 不替代知识文档，引导只讲操作路径。

## 2. 自由组合策略

### 2.1 参考 vnpy 的部分

vnpy 的 `CtaTemplate` 把「策略 = 参数 + 变量 + 生命周期 + 委托」分开。这里保留同样的分层，
但把「策略逻辑」从代码换成**声明式条件表**：

| vnpy | 本软件 |
|---|---|
| `parameters = [...]` | 条件参数 + 退出参数，写进 JSON |
| `on_init` / `on_start` | `RuleStrategy.__init__` / `on_start` |
| `on_bar` 里手写 if | 引擎按条件表求值 |
| `buy/sell/short/cover` | `ctx.buy` / `ctx.close`，风控与费用不变 |

### 2.2 条件 DSL

一条规则档案：

```json
{
  "kind": "rules",
  "name": "我的突破+RSI 策略",
  "rules": {
    "match": "all",
    "entry": [
      {"type": "breakout", "period": 20},
      {"type": "rsi_low", "period": 14, "level": 30}
    ],
    "exit": {"stop_pct": 5.0, "take_pct": 20.0, "ma_period": 0, "max_hold_days": 30},
    "weight": 0.2
  }
}
```

支持的入场条件：

| type | 中文 | 参数 | 触发条件 |
|---|---|---|---|
| `ma_cross` | 均线金叉 | fast 2–120、slow 5–250 | 快线上穿慢线 |
| `breakout` | 突破前高 | period 5–250 | 收盘价 > 前 N 根最高价 |
| `rsi_low` | RSI 超卖回升 | period 2–60、level 5–50 | RSI 从 level 下方回升到上方 |
| `boll_low` | 布林下轨 | period 5–120、k 1.0–4.0 | 收盘价低于下轨 |
| `momentum` | 动量 | period 5–250、pct 0.5–50 | N 日涨幅 ≥ pct% |
| `volume_surge` | 放量 | period 5–120、ratio 1.0–10.0 | 成交量 ≥ N 日均量的 ratio 倍 |

`match`：`all` 全部满足（默认）/ `any` 任一满足。上限 4 条，避免把回测变成曲线拟合。

退出规则（均可关闭）：

- `stop_pct`：收盘价相对持仓成本下跌超过阈值 → 清仓；0 关闭；
- `take_pct`：上涨超过阈值 → 清仓；0 关闭；
- `ma_period`：收盘价跌破 N 日均线 → 清仓；0 关闭；
- `max_hold_days`：持有满 N 个交易日 → 清仓；0 关闭。

仓位 `weight` 5%–50%，默认 20%。

### 2.3 求值顺序

每个标的、每根 K 线：

1. 若有持仓：先判退出（止损 → 止盈 → 跌破均线 → 到期），触发则清仓并返回；
2. 若空仓且距上次下单已过 1 根 K 线：按 `match` 求值，通过则以 `weight` 买入；
3. 同一根 K 线最多下一次单；成交在下一根开盘，与其它策略一致。

### 2.4 语言化摘要

保存前界面实时显示一句人话，例如：

> 当 20 日内收盘价突破前高 且 14 日 RSI 从 30 下方回升时买入；止损 5%、止盈 20%、跌破 60 日均线卖出、最长持有 30 个交易日；单标的仓位 20%。

这段文字同时写进策略详情页的「原理」，用户不需要读 JSON。

### 2.5 持久化与兼容

- 仍写入 `strategy_profiles.spec_json`，新增 `kind` 与 `rules` 两个键；**不需要数据库迁移**，
  旧档案没有这两个键时按 `kind="template"` 处理；
- 注册表键仍是 `custom_<profile_id>`；
- 回测页、模拟盘、实盘的策略下拉框自动包含组合策略；
- 组合策略的可调参数只有「单标的仓位」，条件本身在向导里改，避免回测时出现十几个无关参数。

### 2.6 校验与错误

所有校验集中在 `strategy/rules.py`，错误信息面向用户：

- 至少一条入场条件；最多四条；
- 参数越界给出中文范围（如「突破周期需在 5–250 之间」）；
- 快线必须小于慢线；
- 退出阈值范围同模板叠加层；
- 未知条件类型、缺字段、损坏 JSON 都抛 `ValidationError`，加载坏档案时跳过并记日志。

## 3. 新手引导与操作教学

### 3.1 三层结构

| 层 | 入口 | 内容 |
|---|---|---|
| 首次启动 | 欢迎对话框 | 「3 分钟上手」/「先自己看看」；完成状态存 `kv` 的 `onboarding.done` |
| 跨页引导 | 欢迎框、帮助页、设置页 | 7 步：概览 → 数据 → 策略 → 回测 → 模拟盘 → 实盘(可选) → 帮助 |
| 页内教学 | 每页右上角「本页怎么用」 | 3–4 条本页操作要点 + 常见坑 |

帮助页另设「教程中心」：五张卡（先有数据 / 建一条策略 / 回测 / 模拟盘 / 实盘演练），
点击直接跳到对应页面并打开该页教学。

### 3.2 跨页引导的交互

- 半透明高亮框套住目标控件，右侧/下方浮出说明卡：步骤号、标题、正文、`上一步` `下一步` `跳过`；
- 目标控件不存在时降级为页面级说明，不阻塞；
- 引导期间禁止点击被遮住的区域（用覆盖层拦截），`Esc` 退出；
- 每步自动切页，保留用户原有页面状态；
- 完成后写 `onboarding.done=1`，可在「设置 → 外观 → 重新观看新手引导」再次打开。

### 3.3 目标控件

| 步骤 | 页面 | 目标 |
|---|---|---|
| 1 | 概览 | 「三步上手」卡片 |
| 2 | 数据中心 | 「同步真实行情」按钮 |
| 3 | 策略库 | 「新建策略」按钮 |
| 4 | 回测 | 「开始回测」按钮 |
| 5 | 模拟盘 | 「开始」按钮 |
| 6 | 实盘 | 解锁卡片（未启用时提示去设置） |
| 7 | 帮助 | 「本页怎么用」/ 教程中心 |

页面通过公开属性暴露目标控件（`tour_targets()` 返回 `{name: widget}`），引导层只依赖这个接口，
不深入页面内部。

### 3.4 页内「本页怎么用」

`BasePage.help_steps` 是字符串列表；`page_header()` 自动渲染「本页怎么用」按钮，点开一个
通用 `StepsModal`（标题 + 编号列表 + 「开始本页引导」按钮）。页面作者只需写 3 条文案，
不需要改布局代码。

### 3.5 不打扰原则

- 引导永远可跳过，且不会在回测运行中自动弹出；
- 「设置 → 外观 → 显示新手提示与引导」关闭后，欢迎框和页内提示都不再出现，但帮助页入口保留；
- 所有文案用操作动词开头（「点」「选」「看」），不用产品术语。

## 6. 限制与后续

- 条件只作用于单标的，不做跨品种信号；
- 没有参数优化器，避免鼓励过拟合；
- 组合策略的指标窗口用日线收盘序列计算，停牌日按已有 K 线顺延；
- 引导的高亮是矩形覆盖，不支持圆角挖孔（Tk 限制），视觉上以强调框 + 说明卡为主；
- 若后续加入分钟线，规则引擎无需改结构，只改数据源时间框架。
